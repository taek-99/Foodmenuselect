# 회고록

## 기반 작성
- front-end
    - React
    - Next.js
    - Tailwind CSS

- back-end
    - Supabase

---

### React 선정 이유
- 컴포넌트 단위로 화면을 쪼개어 재사용성과 유지보수성이 높음  
- 생태계가 크고 자료가 많아 문제 해결과 확장이 용이함  
- TypeScript와 궁합이 좋아 정적 타입 기반으로 안전한 UI 개발 가능

### Next.js 선정 이유
- 파일 기반 라우팅으로 페이지 구조 설계가 직관적임  
- 서버 컴포넌트, 서버 액션 등을 활용해 백엔드 로직을 한 프로젝트 안에서 처리 가능  
- 이미지 최적화, 코드 스플리팅 등 기본적인 성능 튜닝이 내장되어 있어 초기 설정 부담이 적음  
- Vercel 등과 연계해 배포 파이프라인을 간단히 구성할 수 있음

### Tailwind CSS 선정 이유
- 유틸리티 클래스 기반으로 빠르게 프로토타입을 만들 수 있어 UI 개발 속도가 빠름  
- 별도 CSS 파일 작성 없이 JSX 안에서 바로 스타일을 제어할 수 있어 유지보수가 용이함  
- 커스터마이징 가능한 디자인 시스템(색상, 폰트, spacing 등)을 설정해 일관된 디자인 유지 가능

### Supabase 선정 이유
- SQL에 대한 기본기가 있어 관계형 테이블 설계와 질의가 자연스러움  
- Firebase에 비해 집계/통계, JOIN 등 관계형 데이터 처리에 강점이 있음  
- 오픈 소스로 제공되어 내부 동작을 이해하기 좋고, 필요 시 자체 서버에 배포 가능  
- 인증, 스토리지 등 백엔드 기능을 함께 제공해 초기 백엔드 인프라 구축 비용을 줄일 수 있음
